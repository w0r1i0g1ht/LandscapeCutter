## 方案比较

1. **推荐：每屏冻结窗口，共享物理像素选区。** 每个窗口只处理所属显示器的绘制与逻辑坐标，
   选区、裁剪和跨屏拖动统一使用桌面物理坐标。多窗口生命周期需要协调，但符合已有架构。
2. 单个覆盖虚拟桌面的 Qt 窗口：窗口数量少，但单窗口 DPR 无法直接表达混合 DPI，增加输入和背景映射风险。
3. 仅允许单屏选区：实现较少，但限制多显示器工作流，不作为此次推荐方案。

## 用户交互

- F2 或托盘“截图”启动一次截图。先取得所有显示器的有效冻结图像，再显示遮罩和工具栏。
- 左键拖出矩形；已有选区内部拖动以移动；八个边角手柄缩放；外部拖动创建新选区。
- 允许跨屏选区，显示物理像素宽高；最小有效区域为 1×1 像素。反向拖动归一化，移动与缩放受虚拟桌面边界约束。
- 工具栏提供“复制”“保存”“取消”。Ctrl+C、Enter 或选区内双击复制并结束；Ctrl+S 打开保存对话框；Esc 取消。
- 保存支持 PNG/JPEG，默认 PNG；扩展名与所选编码保持一致，覆盖已有文件前使用对话框确认。
  成功后结束截图；取消文件对话框返回当前选区；失败保留选区并给出可重试提示。
- 截图准备、选区及保存期间再次 F2 不排队、不启动第二组遮罩。

## 模块与数据流

新增 snip 模块，将纯选区模型、冻结图像集合、截图会话协调器、遮罩窗口及图像导出分开。

1. 会话协调器取得 DisplayCatalog 的不可变目录快照及 generation。
2. 复用 IMonitorCaptureService 捕获各显示器，保持调用契约，不并发调用同一单请求服务实例。
   所有屏幕完成前不创建可见遮罩。这是同一批次冻结，不承诺各屏硬件级同时曝光。
3. 工作线程完成 GPU 回读、像素转换；每屏图像尺寸必须匹配目录中的物理范围。
4. 主线程创建每屏遮罩，共用 SelectionModel。输入边界使用原生桌面物理鼠标位置，
   各窗口绘制再转换到屏内逻辑坐标，避免将 Qt 全局逻辑坐标当作物理坐标。
5. 导出以物理像素 1:1 拼接各屏与选区的交集，不按屏幕缩放比例重采样；显示器间空隙填充黑色。
   完全处于空隙内的选区禁止输出。复制和文件编码消费相同的最终图像。
6. 剪贴板操作在主线程执行；图像合成、PNG/JPEG 编码和磁盘写入放在工作线程。
   文件使用原子提交，失败不截断已有文件。退出时取消或收束任务后才释放设备和回读资源。

## 像素与资源约定

- 桌面选区使用左闭右开的物理矩形，支持负坐标；尺寸及内存计算使用检查溢出的宽整数。
- BGRA8 按真实 rowPitch 复制；HDR 浮点帧需明确转换为 SDR sRGB 输出，不能把浮点字节当作 BGRA8。
  转换策略和固定输入测试在实施计划中具体化，PNG/JPEG 首版均输出 SDR。
- 冻结图像是独立拥有的 CPU 数据，不依赖已关闭的 WGC frame/session。
- 分配失败、无效尺寸和无法编码返回结构化错误，不导致进程退出；不记录图像或剪贴板内容。

## 失败与取消

- 任一显示器捕获失败则整批失败，不显示部分屏幕或复用上次截图；保留已有单请求超时保护。
- 设备丢失时整批作废，最多重建设备并重试整批一次，禁止拼接不同设备代际的结果。
- 显示器、排列或 DPI 变化立即使会话失效并关闭遮罩；目录防抖刷新后允许重新截图。
- 回调携带会话身份，取消、退出和新请求后到达的旧回调不得创建窗口或改写结果。
- 完成或取消后关闭全部遮罩、释放冻结图像并恢复空闲。捕获不可用和热键冲突沿用现有降级原则。

## 验收与实施拆分

1. 纯模型：正反向创建、负坐标、移动、八方向缩放、最小尺寸、边界与跨屏空隙测试。
2. 图像路径：rowPitch、逐像素跨屏拼接、尺寸、DPR 独立性、HDR 转换、编码往返及写入失败测试。
3. 会话：全屏完成屏障、失败不显示、取消、重复 F2、过期回调、拓扑变化及设备恢复测试。
4. UI 与入口：每屏遮罩、工具栏、鼠标与键盘操作、托盘同入口和退出清理；检查 JPEG 插件实际部署。
5. 完整构建与默认 CTest、真实桌面测试；补充 README、运行方式和人工验收清单。

真实桌面验收需验证输出不含遮罩/工具栏、冻结后桌面变化不影响输出、复制和保存一致、反复取消无残留。
多屏负坐标与 100%/150%/200% 混合 DPI 要单独记录；现有里程碑 1 证据仅覆盖单屏 3200×2000、200% DPI、SDR，
不能把合成测试当作真实多屏验收。150ms 启动目标需实测并报告，不以单屏历史数据推断多屏性能。
