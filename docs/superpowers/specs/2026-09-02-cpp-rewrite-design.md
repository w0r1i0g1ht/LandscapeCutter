# LandscapeCutter C++ 重构设计

## 1. 背景与决策

LandscapeCutter 当前 Python 原型已经验证了区域框选、屏幕捕获和置顶浮窗的基本交互，但现有实现以固定桌面坐标为捕获源，不具备稳定的目标窗口绑定、GPU 帧链路和可扩展标注体系。

项目从本次重构起停止维护 Python 运行版本，改用 C++20 和 Qt 6。产品方向不是完整复制 Snipaste，而是先建立可靠的截图、标注和静态贴图能力，再以“目标窗口相对区域的实时贴图”形成差异化。

## 2. 产品定位

LandscapeCutter 是 Windows 10/11 上的轻量截图与贴图工具，提供两类核心能力：

1. Snipaste 式静态工作流：快捷截图、基础标注、复制、保存和静态贴图。
2. LandscapeCutter 特色工作流：从目标窗口中选择相对区域，创建持续更新的实时贴图。

### 2.1 首版目标

- 支持 Windows 10 1903 及以上版本，包括 Windows 11。
- 支持多显示器、负坐标和混合 DPI。
- 提供矩形截图选区及可靠的静态截图闭环。
- 提供矩形、椭圆、箭头、画笔、文字和马赛克标注。
- 支持颜色、线宽、撤销和重做。
- 支持复制、PNG/JPEG 保存和多个静态贴图。
- 在静态工作流稳定后提供目标窗口相对区域的实时贴图。
- 提供 x64 便携包和安装包。

### 2.2 首版非目标

- 不提供 OCR、云同步、素材库或序号标注。
- 不提供鼠标或键盘事件向源窗口转发。
- 不支持 Windows 10 1903 之前的系统。
- 不承诺 DRM、受保护内容或独占全屏游戏捕获。
- 不承诺真实最小化窗口仍持续产生新帧。
- 不恢复 Python 原型中的“伪最小化”功能。
- 不在首版实现 macOS 或 Linux 版本。

## 3. 技术方案选择

采用“Qt UI + Windows 原生 D3D11 图形核心”的混合架构。

- Qt 6 Widgets 负责托盘、设置、工具栏、标注交互和普通窗口。
- Win32 负责全局快捷键、单实例和原生窗口互操作。
- Windows Graphics Capture 负责显示器和目标窗口捕获。
- D3D11/DXGI 负责 GPU 纹理、裁剪、交换链和实时贴图显示。
- 静态截图进入标注或导出阶段时才从 GPU 回读为 `QImage`。
- 实时贴图帧始终保留在 GPU 路径，不逐帧转换为 `QImage`。

未采用纯 Qt 栅格捕获方案，因为逐帧 GPU 到 CPU 回读会限制实时贴图性能。未采用纯 Win32/DirectComposition UI，因为它会显著增加选区、文本编辑、设置和 DPI 适配成本。

## 4. 总体架构

```text
Qt 交互层
    │
    ▼
截图 / 标注 / 贴图业务层
    │
    ▼
捕获抽象层
    │
    ▼
Windows Graphics Capture + D3D11 图形层
```

### 4.1 模块边界

#### `app`

负责程序入口、托盘、设置、全局快捷键、单实例和应用生命周期。该模块协调功能，但不实现捕获、标注或渲染细节。

#### `capture`

提供显示器与窗口捕获的统一接口，管理捕获会话、源状态和最新 GPU 帧。Windows Graphics Capture 的具体类型仅存在于 `capture/windows`。

#### `graphics`

管理 D3D11 设备、上下文、GPU 纹理、裁剪着色器、交换链、设备丢失恢复和受控的 CPU 回读。

#### `snip`

负责显示器快照、冻结背景选区层、矩形选区状态机、选区移动和八方向缩放。内部选区坐标统一使用物理像素。

#### `annotation`

保存原始截图、矢量标注对象和工具状态，提供撤销、重做、预览及最终图像合成。标注模型不依赖捕获实现。

#### `pin`

提供静态贴图和实时贴图。两者共享置顶、拖动、缩放、透明度、右键菜单和关闭行为，但分别使用不可变图像和 GPU 实时帧作为内容源。

#### `platform/windows`

封装 Win32 热键、单实例、窗口枚举、DPI、显示器变化和其他平台相关能力，避免平台 API 散落在业务模块中。

## 5. 核心数据与接口原则

### 5.1 捕获帧

捕获帧包含 D3D11 纹理、物理像素尺寸、帧时间戳、捕获源标识和内容尺寸版本。业务层不直接持有 Windows Graphics Capture 的帧对象。

捕获会话只发布最新帧。消费者来不及处理时覆盖旧帧，不建立无界队列，避免实时贴图延迟逐步累积。

### 5.2 坐标体系

- 显示器、截图、纹理裁剪和标注底图统一使用物理像素。
- Qt 逻辑坐标只存在于窗口布局和输入边界。
- 每次输入转换都携带其所属显示器和设备像素比。
- 实时区域保存为目标窗口内容中的相对物理像素矩形。
- 显示器重排、DPI 变化或目标窗口尺寸变化时重新计算映射，不复用失效缓存。

### 5.3 静态与实时内容

静态贴图持有最终合成图像，与桌面和原截图源完全解耦。实时贴图持有捕获源标识与窗口相对区域，通过 GPU 裁剪当前最新帧。

两类贴图可以共享窗口外壳和交互控制，但不共享强制统一的渲染实现。

## 6. 用户流程

### 6.1 静态截图

```text
F1
→ 在工具遮罩出现前抓取全部显示器快照
→ 创建各显示器的冻结背景选区层
→ 用户框选、移动或调整区域
→ 进入标注状态
→ 复制、保存或创建静态贴图
```

选区层显示冻结快照，因此不会捕获 LandscapeCutter 自身遮罩，也不会因桌面内容继续变化而干扰选择。

### 6.2 静态贴图

静态贴图默认无边框并置顶，支持拖动、缩放、透明度、右键菜单和双击关闭。允许多个贴图并存。贴图的缩放只改变显示尺寸，不改变原始图像数据。

### 6.3 实时贴图

```text
Shift+F1
→ 选择目标窗口
→ 捕获目标窗口的一帧作为选区背景
→ 选择窗口内部的相对区域
→ 建立窗口捕获会话
→ 在 GPU 上裁剪最新纹理
→ 在实时贴图交换链中显示
```

源窗口移动或被普通窗口遮挡时，相对选区语义保持不变。源窗口关闭时，贴图进入“捕获源已关闭”状态。源窗口最小化后若停止产生新帧，贴图显示明确的暂停状态，不伪造持续更新能力。

### 6.4 默认快捷键

- `F1`：静态截图。
- `Shift+F1`：创建实时区域贴图。

快捷键在产品化阶段允许用户修改，并检测系统级冲突。

## 7. 标注设计

标注文档由不可变底图、可编辑矢量对象集合、当前选中对象和命令历史组成。

首版工具包括：

- 矩形
- 椭圆
- 箭头
- 自由画笔
- 文字
- 马赛克

所有工具必须支持颜色或线宽等适用属性，并通过命令模型支持撤销和重做。编辑预览与复制、保存、静态贴图使用同一合成路径，避免输出与预览不一致。

马赛克保留区域和像素化参数，在最终合成时基于底图生成，不保存一次性的低清截图副本。

## 8. 线程与资源模型

- Qt 主线程处理窗口、输入和业务状态，不执行同步捕获、图像编码或磁盘写入。
- Windows Graphics Capture 回调接收 GPU 帧并更新线程安全的“最新帧”槽位。
- 实时贴图渲染消费最新帧；处理速度不足时丢弃中间帧。
- 静态截图回读、PNG/JPEG 编码和保存运行在工作线程。
- 所有 Qt 窗口创建和销毁回到主线程。
- COM 接口、Win32 句柄和 D3D11 资源全部使用 RAII。
- 捕获会话停止后先断开回调，再释放帧池和设备相关资源。

## 9. 错误与状态处理

- 捕获源关闭：停止会话，实时贴图显示源关闭状态，并允许用户关闭贴图。
- 捕获源最小化或暂时无新帧：保留最后一帧并显示暂停状态。
- 目标窗口尺寸变化：更新内容尺寸版本并重新约束裁剪矩形。
- 显示器热插拔或排列变化：取消正在进行的选区并重新构建显示器模型。
- D3D11 设备丢失：停止受影响会话，重建设备一次；失败后进入可恢复错误状态。
- 快捷键冲突：保留应用可用状态，在设置中提示冲突并要求更换。
- 配置损坏：备份损坏文件，恢复默认配置并记录不含用户内容的日志。

日志不得记录截图、窗口画面、剪贴板内容或标注文本正文。

## 10. 工程基线

- 编译器：Visual Studio 2026 MSVC 14.5x；里程碑 0 使用已安装的稳定版
  Visual Studio 18 实例进行构建和测试。
- 语言标准：C++20。
- 最低系统：Windows 10 1903。
- SDK 下限：Windows SDK 10.0.19041。
- UI：Qt 6.8 系列，LGPL 动态链接。
- 构建：CMake 4.4 及以上版本和 CMake Presets；Windows 主预设使用
  `Visual Studio 18 2026` 生成器与 x64 架构。
- 依赖管理：vcpkg manifest；vcpkg 固定到带注释标签 `2026.07.29`。该标签对象 ID
  为 `c76c06644034521fb761a39f8f52d8e87d1103d5`，剥离后的提交（也是检出
  `HEAD`）为 `9e593bb18ea69cc5095e012465dcd675a822ed0d`。
- Windows 资源管理：WIL。
- 日志：spdlog 滚动日志。
- 测试：Catch2。
- 格式化：clang-format，格式规则纳入仓库。
- 目标架构：首版只发布 x64。

### 10.1 工具链固定策略

- 继续使用动态链接的 `x64-windows` triplet，不引入静态 Qt 发布方式。
- `vcpkg.json` 使用上述剥离后的提交
  `9e593bb18ea69cc5095e012465dcd675a822ed0d` 作为 `builtin-baseline`，并通过版本 override
  将 `qtbase` 固定为 `6.8.2#2`；不得直接采用该 baseline 默认的 Qt 6.11。
- 根 CMake 配置继续拒绝 Qt 6.9 及以上版本，并验证实际解析结果为 Qt 6.8.2。
- 引导脚本必须分别验证 exact tag 名 `2026.07.29`、带注释标签对象类型与对象 ID、
  剥离提交、`HEAD`，并拒绝 staged 或 unstaged 的 tracked 改动；无关 untracked 文件
  不影响固定身份。不能只凭 `git describe` 的标签名复用检出，也不能使用未固定的
  `master` 或滚动安装。
- 本次修订复用现有 Visual Studio 2026，不安装 Visual Studio 2022 Build Tools，
  也不通过补丁伪装旧 vcpkg 对 VS 18 的支持。
- 未来可以增加 VS 2022 或 Ninja 兼容预设，但它们不属于里程碑 0 的验收范围。

## 11. 测试策略

### 11.1 单元测试

- 逻辑坐标与物理像素转换。
- 多显示器负坐标和边界相交。
- 选区创建、移动、缩放、确认和取消状态。
- 实时窗口相对区域约束。
- 标注对象序列化与合成参数。
- 每类标注命令的撤销和重做。
- 配置加载、损坏恢复和快捷键冲突状态。

### 11.2 图像测试

为矩形、椭圆、箭头、画笔、文字和马赛克建立固定输入与基准输出，比较合成结果。对抗锯齿允许小范围像素容差，但图像尺寸和坐标必须完全一致。

### 11.3 集成测试

- D3D11 设备建立与销毁。
- 显示器单帧捕获和 GPU 到 CPU 回读。
- 目标窗口捕获及尺寸变化。
- GPU 区域裁剪和交换链呈现。
- 多个贴图建立、关闭和资源释放。
- 设备重建后的捕获恢复。

### 11.4 人工测试矩阵

- 单显示器与多显示器。
- 显示器位于主屏左侧或上方形成负坐标。
- 100%、150% 和 200% 混合 DPI。
- SDR 与 HDR 桌面。
- 集成显卡、独立显卡和混合显卡设备。
- 显示器热插拔、休眠恢复和锁屏恢复。
- 源窗口移动、遮挡、缩放、最小化和关闭。
- 多个静态贴图及多个实时贴图持续运行。

## 12. 性能与稳定性目标

- 常规桌面环境中，从快捷键触发到选区层出现不超过 150 毫秒。
- 选区和标注交互按当前显示器刷新节奏呈现。
- 实时贴图提供 15、30 和 60 FPS 上限，默认 60 FPS。
- 实时链路不进行逐帧 GPU 到 CPU 回读。
- 消费速度不足时丢弃旧帧，不允许延迟持续累积。
- 多贴图连续运行 8 小时后，进程内存、句柄和显存不存在持续增长趋势。

## 13. 实施里程碑

### 里程碑 0：冻结 Python 原型

给当前提交打 `python-prototype-final` 标签；更新 README；从主分支删除 Python 运行代码和失效配置；建立可启动、可测试的 C++/Qt 工程空壳。

退出条件：程序可启动、托盘可见、测试目标可运行。

### 里程碑 1：Windows 图形基础

实现 D3D11 设备、Windows Graphics Capture、显示器模型、Per-Monitor V2 DPI、全局快捷键和单实例。

退出条件：快捷键可抓取任意显示器单帧，输出物理像素尺寸正确。

### 里程碑 2：静态截图闭环

实现全显示器冻结快照、选区层、选区移动和缩放、剪贴板与 PNG/JPEG 保存。

退出条件：多显示器和混合 DPI 下稳定截图，输出不包含工具自身窗口。

### 里程碑 3：标注系统

实现六类标注工具、属性编辑、撤销、重做和统一合成。

退出条件：所有工具可撤销和重做，预览、复制与保存结果一致。

### 里程碑 4：静态贴图

实现多个无边框置顶贴图及拖动、缩放、透明度和菜单操作。

退出条件：多个贴图可稳定共存，重复建立和关闭不存在资源泄漏。

### 里程碑 5：实时区域贴图

实现目标窗口选择、窗口相对选区、GPU 裁剪、实时交换链显示和捕获源状态管理。

退出条件：常见机器上稳定达到 60 FPS；源窗口移动或被遮挡不改变相对区域语义；UI 不被捕获阻塞。

### 里程碑 6：产品化

实现设置、快捷键配置、开机启动、日志、配置恢复、安装包、便携包及完整兼容性测试。

退出条件：产出经过测试的 x64 安装包与便携包。

## 15. 验收定义

首版正式发布必须同时满足以下条件：

- 静态截图、六类标注、复制、保存和多静态贴图形成完整闭环。
- 实时贴图绑定目标窗口相对区域，使用 GPU 捕获与裁剪链路。
- Windows 10 1903 和 Windows 11 的 x64 环境可安装或便携运行。
- 多显示器、混合 DPI、设备恢复和八小时稳定性测试通过。
- 不存在已知的截图内容日志泄露或逐帧 GPU 到 CPU 回读。
- README、快捷键说明、系统要求和已知限制与实际行为一致。
